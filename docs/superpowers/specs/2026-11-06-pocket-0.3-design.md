# OpenCode Pocket 0.3 — современный интерфейс, встроенные скилы и скрытая отладка

**Статус:** принято к реализации (0.3.0)

## Зачем

Приложение уже выполняет основную работу: встроенный сервер OpenCode, чат с
потоковым выводом, провайдеры, файлы, скилы, конфиг и миграция. Осталось три
вещи, которые мешают им пользоваться каждый день:

1. Нижний док визуально привязан к полю ввода: `imePadding()` висит на всём
   `Scaffold`, поэтому при открытии клавиатуры вверх уезжает весь низ.
2. В приложении нет скилов, которыми мы пользуемся в Termux, — 42 каталога.
3. Любая проверка требует `uiautomator dump` и тапов по экрану. Это занимает
   телефон и мешает владельцу.

## Цели

- Плавающий док с современными линейными иконками, который не связан с
  клавиатурой и скрывается, когда она открыта.
- Минималистичная тёмно-фиолетовая полировка: воздух, крупные радиусы,
  меньше рамок и капса, акцент только на главном.
- Все 42 скила из Termux внутри APK, с сохранением пользовательских правок.
- Скрытый loopback-канал отладки: состояние, журнал ошибок, логи сервера,
  прокси к API OpenCode. Без открытия порта в сеть и без UI.
- Журнал ошибок и багов, который можно читать снаружи (включая зеркало в
  `/sdcard/OpenCode/.debug/`).

## Не-цели

- MCP, второй агент, proot/Linux-userland, node/python внутри приложения —
  отдельные итерации.
- Автотесты фронтенда: их владелец проверяет вручную.
- Изменение API-слоя, моделей, миграции и логики сервера, кроме точек
  логирования ошибок.

## Визуальное направление (2026)

«Тихий тёмный интерфейс»: почти чёрный фон с мягким фиолетовым свечением,
поверхности без жёстких рамок, крупные радиусы (20–30 dp), много воздуха,
один акцентный цвет. Иконки — линейные, толщина штриха 1.6–1.8, скруглённые
окончания. Никаких заполненных Material-иконок и заглавных подписей на каждом
шаге.

- Фон: вертикальный градиент `#0A0912 → #07080F`.
- Поверхность: `#12111D` с рамкой `#FFFFFF` 6 %.
- Акцент: `#A78BFA`, вторичный — мятный `#6EE7C8` только для статусов.
- Док: плавающая капсула 64 dp, отступ 12 dp от краёв и 8 dp от навигации,
  радиус 30 dp, лёгкая тень. Активный пункт — пилюля `Accent 14 %`, иконка и
  подпись акцентные; остальные — приглушённые.
- Клавиатура: док уезжает вниз и растворяется (180 ms), место под него
  схлопывается; поле ввода поднимается над клавиатурой через `imePadding()`
  только у композера.
- Шапка: компактная, 48 dp, знак `>_` 30 dp, название 15 sp, версия 9 sp,
  справа — точка статуса и подпись. Долгое нажатие на знак открывает скрытую
  отладочную панель.
- Чат: сообщение пользователя — фиолетовый градиентный пузырь справа,
  ответ ассистента — без пузыря; инструменты — компактные сворачиваемые
  карточки; код — тёмная карточка с заголовком языка.
- Композер: плавающее поле 24 dp с рамкой, кнопка отправки внутри поля,
  без полосы-разделителя на всю ширину.

## Скилы

42 каталога (11 МБ, 651 файл) кладутся в `app/src/main/assets/skills/`.
`SkillSeeder` при старте встроенного сервера копирует недостающие файлы в
`files/opencode/home/config/opencode/skills/` и **никогда не перезаписывает**
существующие: правки пользователя и миграция из Termux важнее. Копирование
идёт до запуска процесса, в фоновом потоке старта сервера. `_sources`
(лицензии) входит в поставку.

`cli.json` и `service.json` из Termux не переносятся: первый — тема CLI, второй
содержит пароль сервера. Конфиг приложения живёт отдельно.

## Отладка

`DebugLog` — кольцевой журнал в памяти + NDJSON в
`files/opencode/debug/events.ndjson` (ротация 1 МБ). События: старт/стоп
сервера, смена состояния, ошибки API, ошибки конфига/скилов/миграции,
необработанные исключения. Если выдан доступ ко всем файлам, те же строки
дописываются в `/sdcard/OpenCode/.debug/events.ndjson` — их можно читать
снаружи без `run-as`.

`DebugBridge` — HTTP на `127.0.0.1:4097`, токен в
`files/opencode/debug/token` (0600). Без токена — 401. Эндпоинты:

- `GET /health` — `{"ok":true}`
- `GET /state` — версия, вкладка, связь, сервер, каталог, модель, счётчики
- `GET /events?limit=N` — последние события
- `GET /logs?limit=N` — хвост `server.log`
- `POST /action` — `{"name": ...}`: `restart`, `start`, `stop`, `reload`,
  `skills`, `config`, `prompt` (через API, без UI)
- `POST /api` — прокси к встроенному OpenCode API с сохранёнными учётными
  данными: `{"method":"GET","path":"/api/session"}`. Это позволяет тестировать
  агента headless.

Скрытая панель: долгое нажатие на знак в шапке. Показывает состояние моста,
токен (маскированный), последние события, кнопки «копировать диагностику» и
«очистить».

## Ограничения

- `minSdk 26`, `targetSdk 35`, `compileSdk 35`, arm64-v8a, пакет
  `com.pocket.opencode`, OpenCode `v2.1.4-beta.4b83402a`.
- Без root и без Termux во время работы.
- Канал отладки слушает только loopback; в сеть не выставляется.
- Пароли, ключи провайдеров и токен не попадают в журнал событий.

## Рассмотренные варианты

- **Док:** оставить Material `NavigationBar` и починить только IME — дёшево,
  но не даёт современного вида; кастомная капсула выбрана ради вида и
  независимости от клавиатуры.
- **Скилы:** копировать при миграции — не работает на чистой установке;
  встроенные assets выбраны, потому что приложение должно быть самодостаточным.
- **Отладка:** ADB/uiautomator — занимает экран; loopback-API внутри процесса
  выбран, потому что не мешает владельцу и даёт доступ к настоящему состоянию.
  ADB-туннель снаружи — отдельный риск, не включаем.

## Риски

- Токен моста читается только через `run-as`/`su`; на некорневом устройстве
  внешний агент не подключится, но и данные не утекут.
- Журнал может содержать пути и тексты ошибок; ключи и пароли вычищаются.
- +11 МБ к APK; сборка вырастет примерно на столько же.
