# OpenCode Pocket

Android-клиент со **встроенным настоящим сервером OpenCode v2**. Приложение
самодостаточное: Termux не нужен ни для запуска, ни для работы. Сервер, поиск
по файлам и скилы уже внутри APK, UI подключается к серверу автоматически.
Импорт из Termux остался только необязательным способом перенести старые
сессии, скилы и ключи.

- Пакет: `com.pocket.opencode`
- Версия: `0.8.3` (`versionCode 23`)
- Один APK: `targetSdk 28` — внутри proot и Ubuntu (см. «Pocket Dev»)
- Минимальная Android: 8.0 (API 26)
- ABI: только `arm64-v8a`
- Сервер: `2.1.4-beta.4b83402a`

## Что умеет

- Встроенный сервер OpenCode в foreground-сервисе: уведомление «OpenCode
  работает · порт …», кнопка «Стоп», сервер переживает свайп из recents.
- Release-сборка с R8: APK около 69 МБ, холодный старт UI ~0.4–0.6 с,
  встроенный сервер готов ~2.5 с (замеры на Mi 9T). Повторные self-test
  `rg`/`pocket-rs` и обход 651 файла скилов кэшируются до обновления APK,
  а соседняя вкладка не составляется до первого свайпа.
- Автоподключение UI к случайному порту и паролю, который сервер печатает
  при старте. Пароль нигде не сохраняется во встроенном режиме.
- Внешний режим для отладки: адрес и пароль задаются вручную.
- Стриминг текста, reasoning, tool calls, shell-команд и их вывода,
  permission-диалоги и формы.
- Сессии, черновик, выбранная модель/агент, вкладка и кэш переписки
  переживают поворот экрана и перезапуск приложения.
- Свои провайдеры и API-ключи: Anthropic, OpenAI, OpenRouter, Google,
  DeepSeek, xAI, Groq, Mistral и остальные из каталога OpenCode.
- Веб-поиск через встроенный `websearch`: Exa, Tavily, Firecrawl, Parallel
  и TinyFish. Ключ подключается в «Модели», провайдер по умолчанию
  задаётся в `opencode.json`.
- Скилы: просмотр, создание, редактирование, удаление, глобальные и
  проектные, встроенные — только чтение. Агент по запросу ищет скилы в
  skills.sh и GitHub, скачивает и ставит их командой `pocket-skill`.
- Обновления приложения из GitHub Releases: проверка, скачивание APK и
  системный установщик без перехода в браузер. SHA-256 проверяется до
  установки.
- Встроенный `ripgrep 15.2.0` (`librg.so` + `libpcre2-8.so` в APK): агент
  ищет по файлам без Termux. `rg` появляется в `files/opencode/tools` и
  в `PATH` сервера автоматически.
- Картинки в чате: вложение из галереи или камеры сжимается до 1600 px
  по длинной стороне, поворот EXIF учитывается. Отправка доступна только
  для моделей с поддержкой изображений — в списке моделей есть бейдж
  «vision», остальные модели заблокированы для вложений.
- MCP: удалённые серверы (Context7, DeepWiki и любые свои по URL) с
  подключением, отключением, статусом и удалением. Адрес сохраняется в
  `opencode.json` (`mcp.servers.<имя>`), поэтому сервер не пропадает после
  перезапуска.
- 41 встроенный скил уже внутри APK (плюс каталог `_sources` с лицензиями):
  при первом старте сервера они раскладываются в конфиг, существующие файлы
  не перезаписываются. Сервер добавляет к ним 4 своих builtin-скила —
  всего в `/api/skill` видно 45.
- Плавающий нижний док с линейными иконками: не привязан к клавиатуре,
  скрывается при вводе, поле ввода поднимается отдельно.
- Чат рендерит Markdown: заголовки, таблицы, списки и чек-листы, цитаты,
  разделители, ссылки, жирный и курсив, зачёркивание и код. Ответ и вывод
  команды копируются одной кнопкой; инструменты показывают параметры и
  результат отдельно, а не сырой JSON.
- «Настройки» разбиты на подразделы — Сервер, Файлы, Окружение, MCP и
  Приложение — вместо одной длинной ленты карточек; сверху всегда виден
  статус сервера и версия.
- Скрытый канал отладки на loopback: состояние, журнал ошибок, логи
  сервера и прокси к API без открытия UI (см. «Отладка»).
- Редактор `opencode.json` с проверкой JSON и перезагрузкой сервера.
- Рабочий каталог на общем хранилище (`/sdcard/OpenCode`) или внутренняя
  папка приложения, если нет разрешения «Память». Если доступ отозван,
  сервер проверяет запись и сам уходит во внутреннюю папку, а не работает в
  недоступном месте.
- Импорт файлов любого формата: кнопка «Добавить файлы в проект» на вкладке
  «Настройки → Файлы» копирует выбранное через системный файловый диалог (SAF) прямо в
  рабочий каталог. Права на всё хранилище для этого не нужны.
- Приём файлов через «Поделиться»: отправь файл (или несколько) из галереи,
  проводника или другого приложения — он окажется в рабочем каталоге.
- Android 13+: фото, видео и аудио читаются через legacy-доступ к хранилищу,
  который даёт разрешение «Память». Отдельные `READ_MEDIA_*` не нужны, потому
  что приложение собирается с `targetSdk 28`.
- Запуск установленных приложений через отладочный мост (`apps`, `launch`),
  без root. `targetSdk 28` не попадает под ограничение Android 10 на фоновый
  запуск activity, но часть прошивок всё равно может его блокировать.
- **Без root.** Сервер, `rg`, `pocket-rs`, файлы и удалённые MCP работают на
  обычном телефоне. Панель «Окружение» показывает фактический список команд,
  доступ к хранилищу и статус оптимизации батареи; тот же список попадает в
  `pocket-environment.md` и `instructions` конфига, чтобы агент не пробовал
  отсутствующие `git`/`node`/`python`.
- Обычное разрешение на память (`WRITE_EXTERNAL_STORAGE`) на всех версиях
  Android: приложение собирается с `targetSdk 28` и работает в legacy-режиме
  хранилища.
- Импорт из Termux с резервной копией текущих данных.

## Первый запуск

1. Установи APK (только ARM64).
2. Приложение запустит сервер и покажет уведомление. Разреши уведомления,
   если Android спросит.
3. На вкладке «Настройки → Файлы» разреши **«Память»**, чтобы агент видел
   `/sdcard/OpenCode`. Приложение собирается с `targetSdk 28`, поэтому на
   всех версиях Android достаточно обычного разрешения: «Настройки →
   Приложения → OpenCode Pocket → Разрешения → Память». «Доступ ко всем
   файлам» не нужен. Без разрешения сервер работает во внутренней папке
   `files/opencode/workspace`, и файлы не видны в проводнике.
4. После выдачи доступа вернись в приложение — сервер перезапустится сам.
   Если экран настроек не открылся, приложение покажет точный путь.
5. На вкладке «Модели» войди в **OpenCode Console** или добавь ключ своего
   провайдера.

## Провайдеры и лимит

Для постоянной работы нужна учётная запись. Открой вкладку «Модели»,
выбери **OpenCode Console** и нажми **«Войти»**: приложение покажет код,
откроет страницу подтверждения и сохранит вход. После этого запросы идут от
твоей учётной записи OpenCode.

Второй вариант — ключ своего провайдера: Anthropic, OpenAI, OpenRouter,
Google и другие из каталога. Запросы тогда идут напрямую в выбранный сервис.

Бесплатные модели OpenCode рассчитаны на ограниченный дневной объём и
сбрасываются в 00:00 UTC. Когда лимит исчерпан, приложение показывает
время сброса и предлагает войти в аккаунт или добавить ключ.

Ключи и токены хранятся в базе OpenCode на устройстве. В логах и интерфейсе
они не показываются.

## Веб-поиск

Встроенный инструмент `websearch` умеет искать через Exa, Tavily, Firecrawl,
Parallel и TinyFish. Чтобы включить поиск:

1. Открой «Модели» и добавь ключ нужного поискового провайдера — он
   сохраняется как интеграция и переживает перезапуск.
2. При желании закрепи провайдера в `opencode.json`:

```json
{
  "websearch": { "provider": "tavily" }
}
```

Без закрепления сервер выбирает доступного провайдера сам и повторяет
запрос при HTTP 429. Если поиск вернул 403 или 429, агент переходит на
`webfetch` и обычный HTML DuckDuckGo.

## MCP

В настройках есть блок MCP: пресеты Context7 и DeepWiki или свой
HTTP/SSE-адрес. Сервер можно подключить, отключить и удалить; статус
(`connected` / `disabled`) виден сразу. Адрес пишется в `opencode.json`,
поэтому после перезапуска сервер поднимается сам. Локальные stdio-серверы
пока не поддерживаются — внутри APK нет `node`/`python`.

## Скилы

Скил — это каталог с `SKILL.md`: frontmatter `name`/`description` и
markdown-инструкции. Встроенные 41 скил лежат в APK и при первом старте
раскладываются в `files/opencode/home/config/opencode/skills`; сервер
добавляет к ним 4 своих builtin-скила, поэтому `/api/skill` отдаёт 45.
Существующие файлы не перезаписываются — правки пользователя и скилы из
миграции остаются.

- Агент видит описания скилов в системном промпте и загружает нужный
  нативным инструментом `skill`, когда задача совпадает с описанием.
- UI: вкладка «Скилы» — просмотр, создание, редактирование и удаление.
  Пользовательские скилы пишутся в `workspace/.opencode/skills` или в
  глобальный конфиг; встроенные доступны только для чтения.
- Новый скил подхватывается после перезапуска сервера: UI делает это сам,
  агент может вызвать отладочный мост `reload`. Без перезапуска список не
  обновляется.
- Установка и обновление: агент получает команду `pocket-skill` в `PATH`.
  `pocket-skill search ЗАПРОС` ищет в skills.sh и GitHub,
  `pocket-skill install ИСТОЧНИК` ставит скил, `pocket-skill update --all`
  обновляет установленные, `pocket-skill list` показывает список,
  `pocket-skill remove ИМЯ` удаляет. Источник — `owner/repo`,
  `owner/repo@skill`, ссылка GitHub или прямой `SKILL.md`; `--project`
  ставит скил в рабочий каталог.
- Установщик пишет ровно в нативный каталог OpenCode, проверяет
  frontmatter `name`/`description`, не перезаписывает существующий скил без
  `--overwrite` и не исполняет чужие скрипты. Рядом с `SKILL.md` лежит
  `.pocket-skill.json` с источником — по нему работают `update` и `remove`.
- В UI вкладки «Скилы» есть «По ссылке» и «Обновить все».
- `skill-library` (AAS) из коробки не работает: он ищет
  `~/skills-library/aas` с 2727 скилами и `python3` в PATH сервера. Ни того,
  ни другого в APK нет; `python3` есть только внутри Pocket Dev. Вместо него
  используй `pocket-skill`.

## Pocket Dev

Приложение собирается с `targetSdk 28`. Это единственный способ запускать ELF
из приватной папки приложения на всех версиях Android: с `target 29+`
действует W^X и `execve()` для `proot` запрещён. Android 14 принимает
`targetSdk` не ниже 23, Android 15 — не ниже 24, поэтому 28 устанавливается
и на них.

Pocket Dev — не отдельный APK, а часть этого же приложения: `proot`,
Ubuntu и команда `dev` уже внутри. Второе приложение и фон не нужны.

Что внутри:

- `proot` 5.x, `libtalloc`, `libandroid-shmem` и ELF-загрузчик proot
  (`loader`/`loader32`) уже в APK.
- Ubuntu 24.04.5 base arm64 скачивается при первом запуске (около 30 МБ,
  проверка SHA-256) и ставится в `files/dev/rootfs`.
- Команда `dev` появляется в `PATH` сервера: `dev apt-get update`,
  `dev python3 …`, `dev /bin/bash`.
- Root и Termux не нужны.

Установка: **Settings → Pocket Dev → «Установить Ubuntu»**. После установки
кнопка «Проверить окружение» запускает внутри rootfs фиксированный набор
проверок: оболочку, разрешение симлинка `python3`, сам `python3`, модули
`json`/`ssl`/`sqlite3`/`urllib`/`zlib`/`bz2`/`lzma` и `git`. Отсутствие
пакета — не ошибка; ошибка запуска при наличии файла означает, что файлы
потеряли SELinux-метки (так бывает после `apt`, запущенного из root-оболочки).
В этом случае панель предлагает «Переустановить»: Ubuntu скачивается заново,
пакеты внутри окружения теряются. Свободного места нужно около 0.5 ГБ
(архив + распаковка + запас).

Ограничения Pocket Dev:

- `proot` — эмуляция системных вызовов, а не виртуализация: скорость ниже
  нативной, `ptrace`-отладка внутри гостя ограничена.
- На устройствах с 16 КБ страницами памяти proot ещё не проверен;
  «Диагностика» показывает размер страницы и статус proot/загрузчика.
- Удаление приложения удаляет rootfs; обновление APK — нет.

## Перенос из Termux

В Termux:

```bash
mkdir -p /sdcard/OpenCode/import
tar czf /sdcard/OpenCode/import/opencode-backup.tar.gz -C $HOME \
  .local/share/opencode .config/opencode
```

Затем в приложении: «Настройки → Файлы» → «Перенос из Termux» → укажи путь к архиву →
«Проверить архив» → «Импортировать». Текущие данные сохраняются в
`files/opencode/backup-<дата>`, старые пути Termux переписываются на
`/sdcard/OpenCode`. После импорта сервер перезапускается.

## Где что лежит

Всё приватное — внутри приложения, без root:

| Что | Путь |
| --- | --- |
| HOME / XDG | `files/opencode/home` |
| База OpenCode | `files/opencode/home/data/opencode/opencode.db` |
| Конфиг | `files/opencode/home/config/opencode/opencode.json` |
| Скилы | `files/opencode/home/config/opencode/skills` |
| Логи сервера | `files/opencode/logs/server.log` |
| Журнал отладки | `files/opencode/debug/events.ndjson` |
| Токен отладочного моста | `files/opencode/debug/token` |
| Встроенный `rg` | `files/opencode/tools/rg` |
| Pocket Dev: proot + загрузчик | `files/dev/bin` |
| Pocket Dev: Ubuntu rootfs | `files/dev/rootfs` |
| Pocket Dev: обёртка `dev` | `files/opencode/tools/dev` |
| Зеркало журнала | `/sdcard/OpenCode/.debug/events.ndjson` |
| Рабочий каталог | `/sdcard/OpenCode` (или `files/opencode/workspace`) |
| Резервные копии | `files/opencode/backup-*` |

База содержит сессии и ключи провайдеров в открытом виде. Копируй её только
в доверенное место. Штатного экспорта настроек в UI пока нет: для переноса
на другое устройство используй копию каталога `files/opencode` (например,
через `run-as`/ADB на отладочной сборке).

## Отладка

Скрытый мост слушает только `127.0.0.1` (порты 4097–4100) и требует токен
из `files/opencode/debug/token`. Без токена — `401`. Актуальный порт виден в
панели: если 4097 занят другим приложением, мост берёт следующий свободный.
Панель открывается долгим нажатием на знак `>_` в шапке: там состояние моста,
последние события, копирование диагностики и очистка. Токен в панели и в
ответах `/state` замаскирован.

```bash
TOKEN=$(run-as com.pocket.opencode cat files/opencode/debug/token)
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:4097/health
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:4097/state
curl -H "Authorization: Bearer $TOKEN" 'http://127.0.0.1:4097/events?limit=50'
curl -H "Authorization: Bearer $TOKEN" 'http://127.0.0.1:4097/logs?limit=100'
curl -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"restart"}' http://127.0.0.1:4097/action
curl -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"method":"GET","path":"/api/session"}' http://127.0.0.1:4097/api
```

Действия `/action`: `start`, `stop`, `restart`, `reload`, `skills`,
`mcp`, `config`, `prompt` (`{"name":"prompt","text":"…"}`), `apps` (список
приложений с launcher-activity) и `launch` (`{"name":"launch","package":"…"}`).
Скилы: `skill-search` (`{"query":"…"}`), `skill-install`
(`{"source":"owner/repo@skill","project":false,"overwrite":false}`),
`skill-update` (`{"skill":"…"}` или `{"all":true}`), `skill-remove`
(`{"skill":"…"}`) и `skill-list`. После установки мост сам вызывает `reload`.
Запуск работает, пока OpenCode Pocket на экране. Пароли, токены и ключи
провайдеров вычищаются из журнала и из ответа `/logs`.

## Обновления

Приложение проверяет `releases/latest` нашего GitHub-репозитория при старте
(не чаще раза в 12 часов) и вручную в «Настройках». Если релиз новее,
показывается диалог с заметками; по кнопке APK скачивается во внутренний
кэш, сверяется SHA-256 из `digest` ассета и передаётся `PackageInstaller`.
Android всегда показывает системное подтверждение — полностью тихая
установка rootless невозможна. Если установка неизвестных приложений
запрещена, приложение открывает нужный экран настроек.

К каждому релизу прикладываются `app-release.apk` и `version.json`
(`{"versionCode":23,"versionName":"0.8.3"}`). Если `version.json` нет,
версия берётся из тега. Релизы с `prerelease`/`draft` игнорируются.

## Сборка

```bash
# локально (нужен Android SDK 35 и JDK 17)
./gradlew assembleRelease

# или удалённо, если настроен POCKET_HOST/POCKET_PASS
bash scripts/remote.sh sync
bash scripts/remote.sh test '*'
bash scripts/remote.sh build          # debug
# release: bash scripts/remote.sh release
```

Release APK: `app/build/outputs/apk/release/app-release.apk`, около 100 МБ.
Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Внутри — бинарник сервера `lib/arm64-v8a/libocserver.so`, `librg.so`,
`libpcre2-8.so`, `proot` с загрузчиками и 41 встроенный скил. Release подписан
тем же ключом, что и прежние сборки, поэтому ставится поверх без удаления
данных; `run-as` работает только на debug-сборке.

## Ограничения

- Только ARM64: x86-эмулятор не подойдёт.
- MCP только удалённые (HTTP/SSE). Локальные stdio-серверы требуют
  `node`/`python` внутри сервера и пока не поддерживаются.
- `opencode.json` с комментариями (JSONC) не редактируется автоматически:
  MCP в таком случае подключается только на текущий запуск. Держи конфиг
  строгим JSON, чтобы серверы сохранялись. Старый `config.json` читается
  только как запасной источник для редактора и сервером игнорируется.
- Картинки принимают только vision-модели. Текущая модель должна быть
  выбрана вручную; для не-vision модели кнопка отправки с вложением
  блокируется.
- Вход в OpenCode Console выполняется по коду устройства: приложение
  показывает код и открывает страницу подтверждения в браузере.
- Без ключа поискового провайдера `websearch` работает в keyless-режиме и
  может упереться в лимит провайдера (402/429). Подключи ключ Exa или Tavily
  в «Модели» либо используй `webfetch`.
- Сервер слушает только `127.0.0.1`; не выставляй его в интернет.
- Pocket Dev встроен в приложение и требует `targetSdk 28`; на 16 КБ
  страницах памяти он ещё не проверен.
- Для работы сверх бесплатного дневного объёма нужен вход в OpenCode
  Console или ключ своего провайдера.
